# Pyramids 动作采集与独立玩法分析

32721 的新动作通道把采集完整性与玩法分类分开。固定官方客户端已有 BET/FREE_GAME 路由证据；新通道继续核请求身份、XML、计数进度、终局和实际金额，陌生展示字段保存在原文中，不要求先给出全部玩法解释。未知请求、未知 FID、错误金额或不完整终局仍拒绝。

新记录使用 `sg-round-evidence-v2`，`bonus=null`、`classificationStatus=pending`，不能把未分类记录冒充普通玩法。原 16,913 条记录使用原适配器，规范化及内容哈希不变。独立分析从已全文读回的 Mongo 记录领取工作，Python 与 collector 对已识别分类相互核对，再保存绑定记录哈希和运行 commit 的不可变 journal；未知分类记录 `review-required`。分析入口没有源 transport、池分配或额度权限，不改原记录，不在请求推进路径执行。

对应 AG 的机制是：以明确的下一步动作推进；完整响应先持久化；玩法解释在独立通道处理；分析错误隔离；采用前独立准入和真实 canary。这里不是取消金额与流程校验，也不是给所有 SG 游戏默认授予同一请求路由。

本机已验证实际 capture、BatchController、DurableQueue、MongoWriter 两局连续推进，以及分类缺口、独立分类不一致、缺全文读回和记录变化的拒绝。Python/Runner 独立新计划接受相同关闭绑定并拒绝改额度或改契约。实际 16,913 条旧记录正式重新准入内存回放通过，原批次与 journal 保持不变，剩余目标 282,937，分页不超过 100。

当前阶段是离线验证，未线上重新准入，未开源，未完成真实 canary；全部效率优化仍未完成。独立分析维护每次最多 100 个序号，不改已应用旧 profile，不重放旧半局。规则卡仍不代表全部玩法覆盖。
