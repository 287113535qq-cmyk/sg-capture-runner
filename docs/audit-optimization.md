# 全量校验加速实测

原实现逐批串行校验，每一局都重新读取并解析固定分类规则。新版按局数均衡分配批次，最多使用 4 个服务端独立进程，每个进程复用自己的 Mongo 连接，并缓存不可变部署版本中的分类规则。20 个 GitHub 采集节点的工作方式保持不变。

| 验证范围 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 同一组 200 批、13,851 个完整局 | 34.750 秒 | 12.262 秒 |
| 游戏 32630 的 299,900 个新增完整局 | 565.138 秒 | 187.860 秒 |

第一行是同一批数据的前后实测，统计完全一致。第二行的旧值是采满到原校验回执落盘的时间，包含校验交接；新值是优化版完整复核的实际墙钟耗时，测试时下一款游戏仍在采集。服务器负载会影响耗时，不能将约 3 倍的实测改善视为所有游戏的固定保证。加上此前核对的 100 个历史局，这款累计达到 300,000 局。

全部记录仍逐条检查原始文件、标准化文件、SQLite 日志、协议结算、bet/mul/buy/bonus、内容摘要和 Mongo 完整文档；数量、连续局号和总额核对均保留。没有改为抽样。并行校验的 Mongo 连接在 Python 和数据库桥两层限制为只读，任一批次失败都不能产生通过回执。

Windows、Linux 分别通过 108 项 Python 测试。新增验证覆盖并行与串行结果一致、原始文件损坏、Mongo 内容篡改、未完成批次拒绝、只读限制和分类缓存一致性。真实全量复核通过 299,900 局，含 6,080 个自然免费大局，共 361,485 个源响应步骤。

服务端运行版本为 `2f9aa749f994b5297788aa57389c839d6b7ac195`，已部署。采集计划和分类表与旧版本逐字节一致；已建立的采集连接继续处理当前游戏，后续新连接及下一次独立校验使用新版。没有重启采集、重发下注、修改配额或启动第二轮。部署后原运行 `36338315642` 的 20 个采集 job 继续运行，游戏 32633 已确认入库超过 10 万局，失败标记为空。
