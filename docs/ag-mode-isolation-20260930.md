# AG模式：单游戏暂挂与队列接续

对照只读 Git 检出中的 `capture-ag/src/ag.round.ts`、`ag.scheduler.ts` 与 `scripts/rolling-worker.ts`：AG按下一动作推进至明确可投注终态，完整入库后计数；确定性协议缺口阻断对应游戏，通道继续下一游戏。AG并非无限丢弃特殊局。此次借鉴失败隔离和调度，不照搬AG字段、八线程参数或近似数量容差。

本次修正两个实际断点：`UNSUPPORTED_BEAVER_NESTED_FEATURE`此前未进入单游戏适配错误分类；工作流接续要求整个矩阵成功，无法在游戏协议失败后接下一款。

- 明确列举适配缺口，按游戏暂停新BET。其他仍在运行的正常大局仅允许原继续请求直至结算，不能借此新增BET、INIT或注册新会话。共享存储、金额、未知响应、源拒绝与资源保护保持共同停止。
- 失败分片先把完整积压幂等落库并全文读回，再将半局写入私有`abandoned-demo`日志并读回；清掉活动pending，不续接、不计完整。不成功留样/落库则不释放现场，并触发存储保护。
- 全部分片释放后创建带内容hash的独立暂挂档案和`game-repair`任务，campaign引用修复任务。旧`parked:<trial>`档案不覆盖；旧流程只保留兼容，不复用旧许可。
- 收尾job可在采集矩阵失败后完成暂挂检查。仅正式开启、无共同hold、当前游戏已暂挂或终审完成且下一款ready时，派一次新的完整矩阵。旧矩阵不能转到下一款，短采许可不扩展。
- 正式round-one使用稳定独立并发组；续采检查只对两条已隔离旧run进行精确身份、撤销/接替回执及jobs0核验，其他活动run一律阻断，保留30秒鲜度与派发意图幂等。不会因已知旧queued无限等待，也没有任意忽略列表。

修复任务只描述等待适配，不是自动修复器或源许可。ready为空时仍明确退出；不能将needs-adapter直接标ready。下一款最低适配、完整计数activation与正式新许可仍需完成。此次不新增Beaver/Demon采样额度，也不把源码上线说成已开始采集。

实际生产类的合成回归覆盖：capture先保存一完整局、下一局适配失败，完整局保留/半局作废/全局hold不触发；修复队列生成后新run选B；同局正常FREE能结束而下一BET被拒绝；归档失败留pending并共同停；旧档案保全；短采、活租约、其他run、迟到job、失效回执、过期查询和重复派发拒绝。源与协议parser使用合成夹具，不代表新SG局或玩法覆盖。

既有未提交的count模式退休改动随本次保留：完整readback后一次释放未用预约，序号不回退；没有创建计数activation。当前通用退休的旧批次数量边界仍未扩至正式全量。
