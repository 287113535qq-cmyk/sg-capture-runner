# 32739 暂挂恢复操作器（Mongo v2）

本实现接续已经成功下注的自然免费局，保留 164 个完整日志和 6 个未完成局；不删除自然触发、不重新 BET。它与 Panda 网络未知 BET 的归档操作器分开，不能互相替用。恢复逻辑仅在 GitHub 运行，服务器只执行原生 Mongo 读写和系统指标读取。

## 当前实施状态

操作器、Runner 接续和短采运行绑定已经实现。Windows / Linux 各 224 项 Python、69 项 Mongo v2 Runner、34 项协议 Node 测试通过；Linux 的 25 项 collector、TypeScript 和 3000 局离线集成通过。预检 [36487710120](https://github.com/287113535qq-cmyk/sg-capture-runner/actions/runs/36487710120) 固定提交 `5812f3d`，没有 SG/数据库连接；原私有现场只读审查也通过。**尚未执行线上恢复、未创建可应用的运行时 proof，也未验证真实 FID1 结算。** `config/protocol-demon-20260929.json` 是固定旧现场和候选代码的审查锚点，不是已恢复的证明。

新增的 `protocol-recover`、`protocol-validate`、`protocol-formal` 都使用原 `trial-300k.yml` 并发锁，不会自动触发。维护步骤没有 SG 配置或源请求能力。正常采集路径继续使用原来的资源保护、意图/响应持久化、固定会话和批次分配。

## 进入恢复的条件

- primary 无活动游戏、无终审、没有 ready 游戏；正常可采游戏优先。本次不会取消正在采集的游戏来腾出恢复窗口。
- 两仓库所有运行/排队列表完整可读，除本次维护运行外均为空。两个 global-hold 必须为 false；本操作器不能解除任何共同保护。
- 32739 的原池及全部 15 个批次与固定锚点、原 parked 日志逐条一致；原会话、已分配范围、配额、计划未变，所有租约均已结束。
- 6 个 pending 都有完整响应且 awaiting=null，新适配器独立解析下一步均为 FREE_GAME。未知源结果、bootstrap 在途、别的失败或任何摘要变化都拒绝。
- 代码文件以 UTF-8/LF 的 SHA256 固定，防止跨平台换行改变证据。不同代码不能直接套用此锚点。

## 三阶段流程

1. `protocol-recover` 先重放核验所有旧完整记录，检查已有 Mongo 全文和缺失范围，再在私有 `capture_journal_v2` 写入完整 campaign/pool/batch/parked 快照及各批完整局副本。完整备份回执保存后才允许状态修改。运行时 proof 绑定这次快照、记录摘要、代码和时间；重复执行一律拒绝。
2. 补齐旧待落库记录并全文读回；原 6 个 pending 原样保留。为每个原局生成绑定计划、worker、会话、原始摘要和代码提交的两小时接续许可。Runner 接管时再次解析，原子消费许可，从 FREE_GAME 接续，不执行新 INIT 或重复 BET。原 failure 仍保存在不可变备份内。
3. 单独派发原 capture 工作流，`allocation=round-one`、`round_one_limit=10`。20 个 worker 各完成 10 局，其中包含原 6 局的结算，总数应从 164 增为 364。campaign 将短采绑定到唯一 run/attempt，迟到分片可加入；别的 run、网页重跑、旧代码、定时再次启动都不能继续增加短采量。
4. `protocol-validate` 对全部 364 局做原始/标准化/摘要和 Mongo 全文核验，逐条确认 164 个旧记录未变、6 个原 attempt 和原响应前缀不变，且 batch5/sequence432 确实得到 bonus2 的 FID1 结算。只通过离线回放不满足这一步。
5. `protocol-formal` 必须在上述验收后 15 分钟内执行，且 pool/campaign 摘要仍一致；随后才解除短采限制。恢复、短采、验收、转正式固定同一代码提交；期间不提交新报告改变 main 后直接派发其他版本。

短采的状态查询返回等待审查，原 verify 会关闭该仓库工作流续采入口。验收完成后按既有授权恢复原入口及正式采集。任何中途失败保留私有证据，不盲目重跑恢复、不清 grant、不移交会话；必须重新审查已持久化阶段。

## 验证覆盖

专项测试覆盖：不抢占正常/ready 游戏；租约、队列和共同保护；篡改原始响应/会话/范围；未知 BET 或 FREE_GAME；接续许可过期/代码不一致/重复消费；原局先 FREE_GAME 后才允许下一个 BET；备份在修改前完成；写入中断留下可审查现场；短采重复运行被拒绝；原局前缀、attempt、bonus 或 worker 完成数不一致不能转正式。

此操作器只审查 32739 这个固定现场。32714、32717、32836 等其他游戏不能改一个编号便使用；其协议、现场及恢复证据须独立验证。
