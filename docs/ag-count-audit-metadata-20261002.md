# 已结算批次终审的元数据复用

终审以前缓存批次和结算文档，但每条记录仍重复计算同一文档的 hash，首次读取每个批次时还分别调用 Mongo。参考 AG `rolling-worker.ts` 的独立任务验证与 `ag.mongo.ts` 的终局回放分工，本次把已关闭批次的元数据读取合并为最多 100 个固定键，并在同一次终审中只验证一次相同的批次证明。

每条记录仍独立核对 trial、buy、sequence、worker 和 session；完整 XML、金额和原文仍由 Python 验证，Mongo 全文分页、内容 hash、规则证据和最终 campaign CAS 不变。缓存仅存在于一次终审，不缓存源许可或健康允许标志。缺批次、缺结算证明、证明 hash 不符和记录跨会话都拒绝完成。正在采集的固定运行不热改。

本机使用实际冻结的 2,859 个批次元数据，构造其 265,702 个已分配记录位置，交错比较三组。元数据读取从 4,076 次降至 42 次，局部元数据验证中位耗时从 1,917.04 ms 降至 44.90 ms。这里没有重新验证游戏原文，也没有模拟网络时延；97.66% 仅是本机元数据阶段下降，不能称为完整线上终审提速。58 项相关测试通过，线上效果仍需新独立终审验收。

本次 Pyramids 接力运行 `37027125803:1` 的 20 个采集任务全部成功，实时原分配计数 299,850、预占 0，加历史 150 达到数量目标。正式完成仍以运行结束后的独立全文终审为准。全部优化和自动跨款接力尚未全部验收。
