# 每游戏分析与规则留档

入口：[178 款游戏档案](game-rules/README.md)。每款有独立 JSON，非敏感规则随代码保存在两个采集仓库；Git 历史保留旧版。它是分析档案，不是实时队列，也不会授权未适配玩法。

## 保存的信息

| 内容 | 保存方式与边界 |
|---|---|
| 游戏及下注条件 | 游戏 ID、运行 ID、普通 buy0 参数、计划摘要；缺失内容为 null |
| 大局开始、继续和完成规则 | BET、FREE_GAME、FEATURE_START/PICK/END 的适用条件；完整序列、余额、奖金及实际下注核验 |
| 特殊环节和协议字段 | 已实现的玩法分类、组合、字段含义和拒绝范围；同一 FID 在不同游戏中分别解释 |
| 已有分析和证据依据 | 每款的专门审查报告、相关分析文档索引、适配器文件及摘要、映射摘要、规则摘要 |
| 实际观察结果 | 新版本终审中统计消息数量、环节间转换、续局数量、实际 bonus 分类，以及指定字段的出现/缺失和值分布 |
| 可追溯性 | 原终审摘要、代码版本、完整规则卡快照、代表性记录 ID 与内容摘要；原始协议继续留在私有数据中 |
| 未完成或未知内容 | 已有 parked 现场及分析文档继续保留；未适配、未观察到、未汇总明确区分，不填成已验证或 0 |

规则卡中的“已配置自然分类数”包括组合 bonus，不等于独立小游戏总数。实际统计只包含本次全文终审通过的新完整局，不包含历史抵扣数、夹具或未完成局。30 万局不是全部玩法覆盖证明；未出现的罕见分支、第一轮关闭的购买或加注玩法都不能算已验证。

## 不增加采集往返

`scripts/build-game-rule-archive.py` 从已有配置、代码和已保存文档生成规则卡，不连接 SG 或数据库。`--check` 在离线 preflight 中检查档案是否与提交一致。

`scripts/runner-v2/game-rule-evidence.mjs` 在原有终审读取并验证每条记录后顺带汇总。没有额外 SG 请求，没有第二遍 Mongo 全量扫描，也不在逐次下注路径增加操作。字段固定，每个字段最多保留 32 个不同的安全值；更多值仅累计截断次数，内存使用有界。缺失字段和显式 0 分开保存，未识别或敏感值仅计数，不写入摘要。

终审完成后，通过原有资源保护通道向已获授权的 `capture_journal_v2` 多写一份小档案：

`<group>/game-rules:<trialId>:<recordsHash>:<archiveHash>`

键包含内容摘要，重复终审得到相同内容时可幂等保存，后续规则版本可另留一份。原 `game-audit` 证明、有效完整记录、配额、会话和玩法判定不变。汇总有少量 CPU 和一次归档写入开销；不是零开销。所有计算在 GitHub，测试服仍只执行 Mongo I/O 和系统指标读取。

## 接入与旧资料

当前已启动的运行保持固定代码版本。此功能随后续运行使用新提交生效，不为留档停止或重启当前采集。已经完成或旧版本运行的游戏，不额外扫描回填观察统计；它们已有的分析、原始链和终审证据保留，规则卡注明未回填。

有协议暂停的游戏仍通过原有 `parked:<trialId>:<batchId>`、`parked-pool:<trialId>` 私有日志保存现场；本文不把这些未完成数据当完整覆盖统计。后续分析应写入针对该游戏的文档并重新生成规则卡，索引会关联包含游戏 ID 的专门分析；跨大量游戏的总表不自动全部复制到每张卡。

公开规则中没有会话值、PID 值、Cookie、密钥、完整启动 URL 或原始 payload。私有原始日志与归档仍按现有备份机制保留。本次新增的 Mongo 档案与原数据同库，不等于新增独立灾备副本；双仓库版本保存的是非敏感分析资料。

验证回执见 [game-rule-archive-validation.json](game-rule-archive-validation.json)。已通过离线兼容性检查；新增私有观察档案仍需由采用该版本的后续真实终审生成，不能把离线测试记为官方玩法覆盖。
