# 四线交接接线与剩余验收

用户要求先打通准入、流程修复、协议分析、采集闭环，再恢复源采集。本次没有派发采集、没有开启源变量、没有改写应用过的许可或额度。

实际对照 AG `scripts/rolling-worker.ts` 的持久领取、结果验证和逐款循环，以及 `src/ag.round.ts` 的动作映射原则。借鉴任务交接与动作/语义分离，不复制在线候选猜测、旧局重放或超额截取。

## 已接线

- `work-line-events.mjs`：带原准入证明和原故障证据的不可变事件。故障投递到独立修复线；修复满足全部六项准备门槛后可返回 admission。迟到旧故障不能撤销新版本，重复事件不重复转换。
- `work-line-mailbox.mjs`：同一真实故障分别交付准入、修复、协议分析。各进程只写自己的库存，避免跨进程覆盖。异常单项进入审查，不退出整个准备进程。
- 准入进程自动发布已经独立审查的 captureHandoff；修复进程自动发布 repair-verified 回执。不在本机生成源许可或调用 GitHub 派发。等待同一缺失证据时不重复改写 inventory，文件更新时间不再冒充实际进展。
- `capture-handoff.mjs`：不再写死 Very Fruity；限定已存在的独立 100 上限、20×5、普通 buy0 profile，验证游戏、组、有效期和六项证明。交接进程核对当前 inventory，已经撤销的版本不能再交接。
- `prepared-campaign-selector.mjs` 已接入实际 `campaign-worker.mjs`。发布库存只缩小已有 online ready 集合；同组、同计划、每项证据全文 hash 一致才可选择。当前发布库存无 prepared 项，不能以旧 ready 集合绕开它。
- 未分类的玩法不进入上述门槛。Very Fruity 的 mysterySymbol 只用于官方 updateMysterySymbol 的符号显示；betID 是元数据，不决定投注或现金变动。动作判断移除 mysterySymbol=0 限制，金额判断移除 betID 非空限制。投注、请求身份、原响应、累计赢分、现金变动与终态确认仍独立验证。
- Very Fruity 明确未审请求/退出分支归为单款流程修复；金额、身份、会话、进度、未知响应和存储错误保留共享保护。

## 实际验证与限制

本机测试覆盖跨线事件、实际文件投递、故障后的下一 prepared 项、修复返回、缺任一门槛拒绝、迟到/重复故障、同组归属和计划变更、过期交接、错误金额和持久化未知。测试中的下一款与修复完成证明是合成数据，不能说已真实切换下一款。

真实 37053154321:1 的留存 Logic 响应包含 mysterySymbol=2 和空 betID。修正后的 Python 独立回放核投注20、赢0、余额100000→99980，判断下一步 EndGame、终态未确认，classification pending、bonus null。未发 EndGame，也未重放或续接旧局。真实故障已由 admission/repair 两进程分别消费；协议观察结果从5增至6。旧 prepared 证明已撤销。原 pending、原文与已经应用的许可保持原样，线上结清仍待独立处理。

当前不能宣布四线全部验收：151 款差异证据尚缺；固定准备处理器尚不能自动完成所有未知协议。修复结果上线、正式可采出版库存、GitHub 故障回执的自动导出/消费，以及实际下一款连续交接仍有缺口。本次不以结构观察、进程存活、空库存接线或合成测试代替这些验收。四线闭环全部通过前继续保持源关闭。

## 持续检查及故障交接补线

固定准备处理器已扩到9款，按真实游戏ID对应检查文件。修复线实跑9款均通过本机检查；32717仍缺处理器。Huff首次失败来自Windows商店python3占位，工作进程和子测试绑定已安装Python后通过。通过检查只生成local gate；其余5项独立门槛未补齐，prepared仍0。未知游戏尚不能自动写适配器，此限制保持明确。

准备进程按源码及证据内容变化唤醒，版本相同的本机通过结果复用；源码换行统一以跨Windows/Linux复用摘要，原始游戏数据不归一化。已有未版本绑定的旧结果不再顶替新代码验证。完整准备结果必须匹配各gate的真实内容摘要和当前版本，不能只提交6个看似合法hash。坏回执单项隔离、检查命令受claim截止时间限制。
