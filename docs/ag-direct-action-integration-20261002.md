# Pyramids 独立动作入口与连续接力准备

当前阶段为实现及离线验证，未应用新版采集 profile，未发出新版源请求。此前完整数据已经通过独立无源结案保留，见 [实际结案](ag-action-layered-close-20261002.md)。累计完成仍为 16/178，不把本报告计作新增完成。

Python、Runner 与 collector 采用独立的 `pyramids-action-v2` 动作合同。首 BET 的直接分层入口按已验证下一步 FREE_GAME 推进；展示字段原样保存并在独立分析通道处理。金额、会话、XML 原文、帧连续性、自然终局和完整 Mongo 读回仍分别验证。旧版记录按原合同解析，132846 条旧规范化的私有回放比较保持一致。

独立计划绑定本次真实关闭记录，完整数 132846、剩余 167004，保留历史基线 150 和总目标 300000。资源预算为 1026 帧、4 MiB 原文。已应用的旧 profile、runtime 和关闭文件保持冻结；新文件名及其工作流选择仅是入口，不产生许可。

参考 AG 的独立任务身份、持久结果复用和连续推进机制，新入口分为受控 canary、主窗口和一次尾段。canary 最多 20 个 worker 各 100 BET，不自动接力。只有该独立 canary 成功并逐批结算，才能生成新的不可变 runtime 绑定。主窗口最多 15 分钟，尾段最多 5 分钟；沿用相同 activation、目标和实际剩余完整数，每个窗口使用新会话。重复 claim、未知写入确认、未完成的父运行、活租约、缺失结算证明或场景变化均拒绝准入。

主窗口取得真实资源证据后才允许尾段。入口并行读取最多四份已成功结束的 capture job 日志，将原始日志保存到私有目录，按固定顺序的 job ID、文件字节及 SHA 生成摘要。该摘要是日志 manifest 摘要，不称为整轮 ZIP 摘要。二十个 worker、服务器与 Runner 必须共同覆盖连续十分钟；缺失分钟、95% 过载或持有保护均不生成接力证明。父运行成功结束由已有认证等待入口核实，不能用运行中状态冒充完成。

离线验证包括真实共用 capture/worker/Python 入口、三方独立规范化、17/121/1026 帧与十二类异常、原版本兼容、重复并发准入、未知 ACK、一次尾段限制、资源日志完整性，以及实际工作流参数、精简读取和增量写入选择。模拟日志与模拟接力只证明代码路径，不能代替线上资源窗口或真实自动接力验收。
